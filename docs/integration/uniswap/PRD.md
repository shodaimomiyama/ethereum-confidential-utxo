- 状態: 要求定義。未解決の論点は「後続で具体化する事項とリスク」に記載する。

## 目的

Confidential UTXOで保有するETHをUniswapの公開流動性で交換し、指定した受取人へ希望する公開トークンを届けられるようにする。
その接続を最初の利用例として、Confidential UTXOを既存のアプリケーションへ組み込む可能性を検証する。

このPRDは接続によって追加する価値と成功条件を定義する。
Confidential UTXO単体の技術的な背景、機能、評価の要求は、[本体のPRD](../../PRD.md)で管理する。

## 背景と課題

機密UTXOを保有して送金できても、公開市場で使うには出金や交換の操作が必要になる。
利用者がそれらの途中状態を管理せず、希望する公開資産で受け取れる利用経路を作る。

[RAILGUN](https://docs.railgun.org/developer-guide/wallet/transactions/cross-contract-calls)などには機密資産とDEXを接続する先行例がある。
本プロジェクトでは、Confidential UTXOで動く利用例と、公開交換で明らかになる情報や追加コストを確認できることを提供価値とする。

## 対象者と利用シナリオ

直接の利用者は、Confidential UTXOでETHを保有し、交換後の公開トークンを指定した受取人へ届けたい人である。
給与支払いや事業者間決済などの特定の事業用途はまだ選定していない。

成果を評価する開発者は、Confidential UTXOと公開交換を組み合わせるために必要な条件や、そこで公開される情報を確認できる。
ハッカソンの審査者には、会期中に開発した接続機能による追加価値を示す。

## 要求と成功の判断

| 要求ID | 要求 | 成功の判断 |
| --- | --- | --- |
| U-01 | 機密UTXOとして保有するETHを公開市場で使える | UTXOから出金したETHをUniswapで交換し、指定した受取人が一種類の公開トークンを受け取れる |
| U-02 | 利用者が出金と交換の途中状態への対処を求められない | 交換に失敗しても、出金だけが確定した状態を残さない |
| U-03 | ハッカソンで接続の追加価値を検証する | 会期中に追加した動く接続機能を示し、Uniswap FoundationのContinuity賞への提出条件を満たす |

U-01とU-02の具体的な保証は後続の要件定義で扱う。
出金と交換を一つのトランザクションとして扱い、交換失敗時にはUTXOの消費と資産移動を取り消す方針は合意済みである。
ガス代は取り消しの対象に含めない。
U-03の応募資格と提出条件は[公式賞金ページ](https://ethglobal.com/events/tokyo2026/prizes/uniswap-foundation)を参照する。

受賞を目指すが、受賞は外部評価であり、Confidential UTXOの技術的仮説が成立することの証明にはしない。

## 今回の範囲と対象外

対象は、ETH専用のConfidential UTXOから出金し、Uniswapで一種類の公開トークンへ交換して指定した受取人へ届ける、一方向の利用経路とする。

研究と検証のためのConfidential UTXOを利用するPoCとし、実資金での本番運用は今回の対象外とする。
接続側のデモの提供形態は、後続で具体化する。

交換金額の秘匿、交換先トークンのプール内秘匿、入力資産の汎用化、ENS連携は今回の必須成果に含めない。
Confidential UTXO内部の対象資産を増やすことも求めない。

交換側の金額と受取人は公開される。
公開市場への出金によって、Confidential UTXO内の過去の金額が推論される場合もある。

## 制約と開発の区切り

| 項目 | 合意済みの方針 |
| --- | --- |
| 基盤との関係 | ETHを対象とするConfidential UTXOを利用する。基盤と接続側の要求、要件、仕様、設計を分ける |
| 応募対象 | ETHGlobal Tokyo 2026のUniswap Foundation「Best Uniswap Stack Contribution」のContinuity枠 |
| 開発時期 | Confidential UTXOは事前成果とし、賞向けの接続機能はハッカソン期間中に開発する |
| 優先順位 | 賞への応募資格を優先し、事前作業の範囲を調整する |

2026年9月22日時点の[公式提出案内](https://ethglobal.com/events/tokyo2026/info/details)では、提出締切は2026年9月27日09:00 JSTである。
Continuityでの正式な参加承認、既存成果の申告方法、開発開始時刻は確認事項として残す。

事前の文書やコードを既存成果として記録し、会期中に開発した接続機能を区別して提出する。
参加資格と提出条件は、[イベントの参加ルール](https://ethglobal.com/events/tokyo2026/info/details)と[スポンサー賞の条件](https://ethglobal.com/events/tokyo2026/prizes/uniswap-foundation)の両方で確認する。

## 将来像と成果の使い方

Ethereumアプリケーションが、必要な金額の機密性とそのコストを選び、既存の流動性を使えるようにする。
今回の接続を、その将来像を検証する最初の利用例にする。

接続のコード、失敗時の挙動、公開情報と追加コストの評価、追試手順を、再利用できる成果の候補とする。
評価方法や提出物の詳細は後続で具体化する。
将来は、小さなSDKや別の接続例を通じて再利用の条件を検証する。
他の機密台帳へ適用できる範囲や、共通化できる部分は未検証である。

## 後続で具体化する事項とリスク

| 論点 | 次に明確にする内容 |
| --- | --- |
| Confidential UTXOとの整合 | 接続が必要とする出金と認可を、Confidential UTXOの公開仕様で満たせるか |
| デモと評価 | 受取人への着金、失敗時の挙動、追加コスト、公開される情報をどう提示し、追試できるようにするか |
| 対象環境 | ネットワーク、交換先トークン、必要な流動性を確保できるか |
| 賞への適合 | 正式な参加枠と申告、会期中の成果の説明、提出条件の充足 |
| 実現性 | 基盤の完成状況を踏まえ、会期中に接続機能を実装して提出期限に間に合うか |
| 利用価値 | 公開市場への出金で金額が推論されることを踏まえても、用途に役立つ機密性が残るか |

Routerの版や交換経路、認可の形式、コントラクトの分割などは、後続の要件定義、仕様書、Design docで具体化する。
実現性を理由に要求を縮小する場合は、その変更をこのPRDへ反映する。
