# Confidential UTXOのPRD（要求定義）

- 状態: 要求定義の各節を合意済み。未解決の論点は「後続で具体化する事項とリスク」に記載する。
- 最終更新: 2026-09-22

- 文書の役割: [文書管理ルール](../.agents/rules/documentation.md)

## 目的

Ethereum上で金額の機密性を持つUTXOを扱う仕組みをEIPとして提案し、Ethereumの共通システムコントラクトとして採用され、利用されることを目指す。
標準化の対象はコントラクトレベルの仕組みとする。
導入と更新の方式、拡張可能な範囲は、後続の仕様と設計で具体化する。

そのために、仕様、参照実装、再現可能な評価を整備し、Ethereumコミュニティが有用性、安全性、機密性の限界、必要なコストを検討できる根拠を提供する。

最初の段階では、公開グラフ型のConfidential UTXOを研究プロトタイプとして実装して評価し、標準化に向けた技術的な成立性と課題を明らかにする。

## 着想の背景

[EIP-8182](https://eips.ethereum.org/EIPS/eip-8182)は、プライベートな資産移転の共通基盤を、Ethereumが管理するシステムコントラクトとして提供する構想を示している。
金額に加えて消費するノートも秘匿するため、ゼロ知識証明による所属確認やnullifierによる二重使用の防止を用いる。

Mimblewimbleで使われるConfidential Transactionsは、金額をコミットメントとして表現し、金額を公開せずに収支の整合性を検証する技術的な出発点となる。
Ethereum上に適用する研究として、Mimblewimbleとzk-SNARKsを組み合わせた[Ethereum 9¾の提案](https://ethresear.ch/t/ethereum-9-send-erc20-privately-using-mimblewimble-and-zk-snarks/6217)も存在する。

本プロジェクトは、UTXOの状態をコントラクトストレージで管理し、消費と生成の関係を公開する方式を検討する。
取引のつながりの秘匿を求めないことで、暗号処理や実装の複雑さを減らし、有用な金額の機密性を提供できるかを検証する。
コスト上の利益は仮説であり、公開された取引関係と既知の入出金額から金額が推論される限界も評価する。

## 背景と課題

金額の公開を避けて資産を移転したい利用者に対し、実行と証明生成の負担を抑えて利用できる基盤を提供したい。

本プロジェクトでは、取引のつながりの公開を許容できる用途を対象に、金額の機密性と利用コストの両立を目指す。
そのためには、公開情報から金額が推論される条件と、実際に必要なコストを明らかにし、どの用途に適するかを示す必要がある。

また、複数のウォレットやアプリケーションが共通して利用できる基盤を目指す。
標準化に向けては、既存方式との差分に加え、Ethereumの共通システムコントラクトとして提供する意義を示す必要がある。

## 対象者と提供価値

| 対象者 | 提供を目指す価値 |
| --- | --- |
| ウォレットやアプリケーションの開発者 | 金額の機密性を扱う機能を、共通の仕様と基盤に基づいて組み込める |
| ウォレットやアプリケーションの利用者 | 取引関係の公開と金額推論の限界を理解したうえで、金額の公開を抑えた資産移転を利用できる |
| Ethereumのプロトコル開発者や研究者など、標準化を評価する人 | 仕様、参照実装、再現可能な評価から、安全性、有用性、コスト、共通基盤として採用する意義を検討できる |

最初のプロトタイプは、方式を実装して検証する開発者と研究者を主な対象とする。
一般利用者向けの完成した送金サービスは初期成果に含めない。
給与支払いや事業者間決済など、特定の用途への適合性は、機密性の限界とコストの評価を踏まえて検討する。

## 要求と成功の判断

以下はConfidential UTXO単体で達成する要求である。

| 要求ID | 要求 | 成功の判断 |
| --- | --- | --- |
| P-01 | 機密UTXOによる資産移転を利用できる | ETHの入金、他者への機密送金、公開ETHへの出金が一連の操作として成立する |
| P-02 | 利用に必要なコストを先行方式と比較評価できる | 本方式と選定した先行方式の実装を用い、実際の暗号検証を伴う実行コストと証明生成時間を、各方式の機密性と機能の違い、測定条件とともに比較できる |
| P-03 | 機密性と限界を評価できる | 公開情報から金額が判明する条件と、不確定性が残る条件を説明して再現できる |
| P-04 | 第三者が実装と評価を再現して検証できる | CLIと再現可能なスクリプトで基本操作と比較ベンチマークを実行できる |
| P-05 | 利用者の資産を正当に扱う | 無断使用、二重使用、不正な資産生成を防ぐための条件と、その検証結果を示せる |
| P-06 | 共通システムコントラクトとして標準化を議論できる | EIP案、参照実装、評価を通じて、既存方式との差分とEthereumが共通基盤として提供する意義を説明できる |

最初の検証ではP-01〜P-05を対象とし、実装と先行方式との比較ベンチマークの結果を[Ethereum Research（ethresear.ch）](https://ethresear.ch/)へ投稿する。
公開した成果をもとに技術的な議論を行い、P-06につなげる。
最終的な成功は、標準として採用され、ウォレットやアプリケーションから利用されることにある。

具体的な安全性の保証、測定条件、合格基準は要件定義で定める。
期待した機密性やコスト上の利益が得られない場合は、その結果をもとに要求や方式を見直す。

## 最初の検証範囲

最初の成果は、実資金を扱わない研究用プロトタイプとする。

| 項目 | 初期成果に含める内容 |
| --- | --- |
| 基本操作 | ETHの入金、他者への機密送金、公開ETHへの出金 |
| 受取人の利用 | 受取人が受領した金額を確認し、そのUTXOを再送金や出金に使える |
| 暗号と安全性 | 実際の暗号検証と、無断使用、二重使用、不正な資産生成を防ぐ条件の検証 |
| 評価 | 本方式の動く実装を用意し、EIP-8182などから選定した先行方式との比較ベンチマークを計測する。実行コストと証明生成時間を比較し、公開情報による金額推論も再現する |
| 成果の公開 | 実装と比較ベンチマークの結果を、再現方法、比較対象、測定条件、各方式の機密性と機能の違いとともにethresear.chへ投稿する |
| 提供形態 | CLIと再現可能なスクリプト |
| 実行環境 | 実資金を扱わないローカル環境またはテストネット上の通常のコントラクト |

必須とする秘匿の対象は金額とし、UTXO所有者のアドレスや公開鍵の秘匿は必須にしない。
これは所有者の公開形式を決めるものではない。
所有者情報の公開が金額推論へ与える影響は評価に含める。

ERC-20対応、取引グラフの秘匿、GUI、本番運用や資金復旧、あらゆる先行方式を対象にした網羅的な性能比較は、初期の必須成果に含めない。
Ethereumの共通システムコントラクトとしての導入は、この検証の後に進める。

## 合意済みの前提と制約

| 項目 | 前提と制約 |
| --- | --- |
| 実行基盤 | Ethereumを対象とする |
| 状態管理 | UTXOの状態をコントラクトストレージに保持する |
| 公開グラフ | UTXOの消費と生成の関係を公開する |
| 機密性の評価 | 公開情報による金額推論を考慮し、公開済みの履歴を後から消せることを前提にしない |

## 後続で具体化する事項とリスク

| 論点 | 未解決の事項とリスク |
| --- | --- |
| 機密性 | 公開グラフ、既知の金額、所有者情報からの推論によって、用途に必要な機密性が残らない可能性がある |
| コスト | 実際の暗号検証と証明生成に必要な負担が、想定する用途に見合わない可能性がある |
| 資産の安全性と信頼 | 使用権限の確認、秘密情報の保管と受け渡し、第三者への信頼が必要になる範囲を明らかにする必要がある |
| 用途への適合性 | 取引関係の公開を許容しつつ、金額の機密性から利益を得られる具体的な用途を検証する必要がある |
| 標準化の意義 | 既存方式との差分、共通システムコントラクトとして提供する利点、導入と更新に伴う責任と権限を明らかにする必要がある |
